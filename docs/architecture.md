# Архітектура

Цільова архітектура дзвонілки. Застосунок і віджет живуть у `apps/web`, сервер у `apps/server`; сторінку демо описано в [demo.md](demo.md).
Цей документ описує, як це побудовано. Розділи додаються поступово.

## 1. Фронтенд: Vue SPA

### Як поставляється

Продукт — **віджет**, який вбудовується в сторонні сайти й застосунки. Окремого сайту дзвонілки немає.

| Режим | Для кого | Вхід |
| --- | --- | --- |
| **Віджет** (основний) | користувачі сайту-господаря | без логіна: сайт-господар передає токен |
| **Демо** | показ продукту, тестування | окрема сторінка з вбудованим віджетом, вхід за ім'ям і номером |

Vue-застосунок один: віджет. Демо — окрема невелика сторінка, яка поводиться як сайт-господар:
сама отримує токен і підключає віджет через `embed.js`. Так демо заодно перевіряє вбудовування.

### Стек

| Що | Вибір | Навіщо |
| --- | --- | --- |
| Фреймворк | Vue 3, Composition API, `<script setup>` | реактивний стан замість ручного `render()` з демо |
| Мова | TypeScript | типізовані стани дзвінка й події сервера |
| Збірка | Vite | швидкий dev-сервер, HTTPS для доступу до камери |
| Стилі | Tailwind CSS 4 | утиліти в шаблонах, дизайн-токени в CSS через `@theme`, світла й темна теми |
| Маршрутизація | Vue Router, `createMemoryHistory` | екрани всередині віджета, не чіпаючи URL сайту-господаря |
| Стан | Pinia | спільний стан дзвінка для всіх екранів |
| Медіа | `livekit-client` | аудіо й відео через LiveKit |
| Переклади | vue-i18n | українська за замовчуванням, рід у текстах («вимкнула»/«вимкнув») |
| Тести | Vitest, Vue Test Utils, Playwright | юніт-тести сторів і e2e-сценарії з демо |
| Якість коду | ESLint, Prettier | єдиний стиль |

### Структура папок

Код SPA лежить у `web/` (після міграції в `apps/web`, див. [project-structure.md](project-structure.md)):

``` text
web/
  demo/           # сторінка демо: вхід за ім'ям і номером, підключає віджет через embed.js (без Vue)
  src/
    app/          # App.vue, router, i18n
    entries/
      widget.ts   # точка входу віджета: токен і налаштування від сайту-господаря
    embed/        # embed.js: невеликий завантажувач, який сайт-господар підключає до себе
      styles/     # main.css: підключення Tailwind і дизайн-токени
    pages/        # екрани-маршрути: Contacts, Recents, Settings
    features/
      call/       # екрани дзвінка, стор, машина станів
      contacts/
      recents/
    shared/
      ui/         # кнопки, аватари, іконки
      media/      # обгортка над livekit-client, пристрої, камера
      sounds/     # гудки й мелодії через Web Audio
      api/        # HTTP-клієнт і WebSocket сигналізації
  tests/e2e/
```

### Стилі

Tailwind CSS 4 підключається через Vite-плагін `@tailwindcss/vite`. Окремого `tailwind.config.js` немає:
у v4 налаштування пишуться прямо в CSS.

```css
/* web/src/app/styles/main.css */
@import "tailwindcss";

/* варіант dark: спрацьовує за атрибутом, а не лише за системною темою */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

/* значення з design/dialer.pen (темна тема) */
:root, [data-theme="dark"] {
  --bg: #0a0c14; --fg: #f3f5fa; --mute: #b4bccd; --line: rgba(255, 255, 255, .18);
  --card-top: #1c2338; --card-bottom: #121726; --stage-glow: #1e2340; --accent-icon: #a5a8ff;
}
/* світла тема: значення з design/dialer.pen (theme mode: light) */
[data-theme="light"] {
  --bg: #eef0f6; --fg: #12151f; --mute: #5b6478; --line: rgba(20, 24, 38, .12);
  --card-top: #fff; --card-bottom: #f1f3fa; --stage-glow: #dfe3f7; --accent-icon: #4f46e5;
}

/* inline: утиліти посилаються на змінні, тому самі перемикаються разом з темою */
@theme inline {
  --color-bg: var(--bg);
  --color-card-top: var(--card-top);
  --color-card-bottom: var(--card-bottom);
  --color-stage-glow: var(--stage-glow);
  --color-accent-icon: var(--accent-icon);
  --color-fg: var(--fg);
  --color-mute: var(--mute);
  --color-line: var(--line);
  --color-accent: #6366f1;
  --color-call-ok: #22c55e;   /* кнопка «Прийняти» */
  --color-call-bad: #f0626b;  /* кнопка «Завершити» */
  --color-warn: #f5b84b;      /* утримання, слабкий сигнал */
  --color-warn-text: var(--warn-text);  /* текст кольорів стану: у світлій темі темніший, див. design-system.md */
  --color-bad-text: var(--bad-text);
  --color-ok-text: var(--ok-text);
}
```

- Кольори, відступи й радіуси беремо з `design/dialer.pen` (дизайн головніший за демо й документи) і оголошуємо як токени в `@theme`.
  Tailwind сам створює з них утиліти, наприклад `text-mute`, `bg-call-ok`.
- У компонентах пишемо утиліти прямо в шаблоні. Повторювані елементи (круглі кнопки дзвінка, аватари)
  виносимо в компоненти `shared/ui`, а не в класи з `@apply`.
- Анімації з демо (пульсація кілець, «дихання» кіл голосу) описуємо через `@keyframes` у `main.css`
  і токени `--animate-*` у `@theme`.
- Поважаємо `prefers-reduced-motion`: анімації вимикаються варіантом `motion-reduce:`.

Повний перелік токенів — у [design-system.md](design-system.md), каталог компонентів — у [components.md](components.md).

### Теми

Дві теми: **світла** й **темна**. Кольори обох — з `design/dialer.pen` (вісь `mode`, див. [design-system.md](design-system.md#світла-тема)).

- Режим теми: `auto` (за `prefers-color-scheme`, змінюється разом із системою), `light` або `dark`.
- **У віджеті** режим задає сайт-господар у налаштуваннях віджета, щоб віджет пасував до його дизайну.
  За замовчуванням `auto`. Сайт-господар може змінити тему на льоту (наприклад, коли в нього самого перемикається тема).
- **У демо** тему обирають перемикачем на самій сторінці демо. Вона передає вибір віджету через `setTheme`
  і зберігає його в `localStorage`.
- **У застосунку** (`entries/app.ts`) тему обирають у налаштуваннях («Авто / Світла / Темна», `usePrefsStore`, лише цей пристрій).
- На `<html>` ставиться атрибут `data-theme="light"` або `"dark"`; для `auto` атрибута немає, і CSS бере системну тему
  (`prefers-color-scheme`), тож змінюється разом із системою без JS.
- Щоб віджет не блимав не тією темою при завантаженні, тема передається вже в URL iframe
  і виставляється до запуску Vue.
- Компоненти використовують семантичні кольори (`bg-card`, `text-fg`, `text-mute`), тож працюють в обох темах
  без змін. Варіант `dark:` лише для рідкісних винятків, наприклад тіней чи зображень.
- Кожен екран перевіряємо в обох темах; контраст тексту не нижче WCAG AA. Текст кольорів стану (`warn`, `bad`, `ok`) у світлій темі
  фарбуємо `text-warn-text`, `text-bad-text`, `text-ok-text`: основні кольори на світлому фоні не дають достатнього контрасту.
- `color-scheme` на `<html>` відповідає темі, щоб системні елементи (скролбари, поля вводу) теж перемикались.

### Маршрути

Маршрути внутрішні: Vue Router працює з `createMemoryHistory`, тому навігація у віджеті не змінює URL і
історію браузера сайту-господаря.

- `/` — контакти;
- `/recents` — історія дзвінків;
- `/settings` — пристрої, звук.

Екран дзвінка не є маршрутом: це шар поверх поточної сторінки, який керується стором дзвінка.
Так дзвінок не обривається під час навігації, а згорнутий дзвінок показується плашкою на будь-якому екрані.

### Вбудовування

Віджет працює в **iframe**, який створює невеликий завантажувач `embed.js`.

```html
<script src="https://<наш-домен>/embed.js"></script>
<script>
  const dialer = Dialer.mount({
    token: '<токен від бекенду сайту-господаря>',
    theme: 'auto',
    locale: 'uk',
    position: 'bottom-right',   // або 'bottom-left'
    offset: { x: 24, y: 24 },
  });
  dialer.on('call:ended', (e) => { /* … */ });
  dialer.setTheme('dark');
</script>
```

- `embed.js` створює iframe з `allow="camera; microphone; autoplay; display-capture"`: без цього браузер
  не дасть доступу до камери й мікрофона всередині iframe.
- Сайт-господар і віджет спілкуються через `postMessage`. Обидва боки перевіряють `origin` повідомлень.
- API завантажувача: `mount`, `unmount`, `open`, `close`, `setTheme`, `setToken`, `call(contactId)`,
  події `ready`, `open`, `close`, `call:started`, `call:ended`, `incoming`, `token:expired`, `error`.

### Плаваюча кнопка

На сайті віджет виглядає як кругла кнопка в кутку екрана, що відкриває панель дзвонілки.

| Стан | Що видно | Розмір iframe |
| --- | --- | --- |
| Згорнутий | кнопка з іконкою телефону й лічильником пропущених | 64×64 |
| Відкритий | панель: контакти, історія, налаштування | 400×640, не більше висоти вікна |
| Дзвінок | панель з екраном дзвінка | як відкритий |
| Телефон (ширина < 480px) | панель на весь екран | 100% × 100% |

- iframe завантажується одразу під час `mount` і тримає з'єднання з сервером, щоб приймати вхідні навіть у згорнутому стані.
- Розмір iframe змінює `embed.js`: віджет повідомляє через `postMessage`, який стан потрібен.
  Поки віджет згорнутий, iframe займає лише місце кнопки й не перекриває сайт.
- Вхідний дзвінок сам розгортає панель. Під час розмови панель можна згорнути: кнопка показує таймер
  і пульсує, дзвінок триває.
- Кнопка й панель мають `z-index` поверх сайту; позицію й відступи задає сайт-господар.
- Клавіша `Esc` згортає панель (але не завершує дзвінок), фокус повертається на кнопку.

Чому iframe, а не вбудовування прямо в сторінку (Web Component):

- стилі сайту-господаря не ламають віджет, а стилі віджета — сайт (Tailwind 4 у Shadow DOM працює не повністю);
- токен і медіапотоки ізольовані від скриптів сайту-господаря;
- віджет оновлюється на нашому боці без змін на сайті-господарі.

### Авторизація

- **Віджет.** Власного логіна немає. Бекенд сайту-господаря отримує в нашого бекенду короткоживучий токен
  користувача й передає його у `Dialer.mount`. Коли токен спливає, віджет надсилає подію `token:expired`,
  і сайт-господар передає новий через `dialer.setToken`.
- **Демо.** Сторінка демо сама грає роль сайту-господаря, див. [Сторінка демо](#сторінка-демо).
  Екранів входу у віджеті немає.

### Сторінка демо

Окрема сторінка `/dialer/`: коротко про продукт, форма входу, а після входу — вбудований віджет,
як на справжньому сайті.

**Форма входу.** Без підтвердження кодом: людина вводить ім'я й номер і одразу входить.

- **Ім'я:** обов'язкове, 2–40 символів, пробіли по краях обрізаються. Його бачать співрозмовники.
- **Телефон:** лише українські номери. Префікс `+380` зафіксований, людина вводить 9 цифр,
  поле показує маску `+380 XX XXX XX XX`. Вставлені `0XXXXXXXXX`, `380XXXXXXXXX` чи `+380…` нормалізуються.
  На бекенд іде формат E.164: `+380XXXXXXXXX`.
- Кнопка «Увійти» виглядає неактивною, поки поля не валідні, але натискання показує всі помилки.
  Помилки під полем з'являються після виходу з нього.

**Вхід.**

1. Сторінка надсилає `{ name, phone }` на демо-ендпоінт нашого бекенду й отримує токен.
   Той самий номер — той самий користувач, ім'я оновлюється. Так двоє можуть дзвонити одне одному.
2. Токен, ім'я й номер зберігаються в `localStorage` сторінки демо (не віджета).
3. Сторінка викликає `Dialer.mount({ token, theme })` і показує в шапці ім'я, номер і кнопку «Вийти».
4. На `token:expired` сторінка мовчки входить знову зі збереженими ім'ям і номером і викликає `setToken`.
5. «Вийти» викликає `dialer.unmount()`, очищає `localStorage` і повертає форму.

Після перезавантаження, якщо токен збережено, форма не показується: віджет підключається одразу.

**Контакти.** Демо-користувач бачить у контактах усіх демо-користувачів, крім себе: ім'я й номер.
Додавати контакти вручну не потрібно. Нижче завжди є демо-співрозмовники зі сценаріями (відповідає,
не відповідає, зайнято), щоб демо працювало й для однієї людини.

**Безпека.** Без підтвердження будь-хто може увійти під чужим номером. Для демо це прийнятно,
але демо-ендпоінт і демо-користувачі мають бути відокремлені від справжніх сайтів-господарів:
демо-токен не дає доступу до їхніх користувачів.

### Сповіщення про вхідні

Вхідні дзвінки мають доходити й тоді, коли вкладку із сайтом закрито, тож потрібні Web Push-сповіщення.

Обмеження браузерів, через які рішення складніше, ніж у звичайного сайту:

- Сервіс-воркер можна зареєструвати лише для власного домену сторінки. Запитувати дозвіл на сповіщення
  з iframe чужого домену більшість браузерів не дозволяє.
- На iPhone і iPad Web Push працює лише для сайтів, доданих на головний екран (iOS 16.4+).

Пропозиція:

1. Сайт-господар розміщує в себе файл `dialer-sw.js` з одним рядком: `importScripts('https://<наш-домен>/sw.js')`.
   Так сервіс-воркер працює на домені сайту, а логіку оновлюємо ми.
2. `embed.js` реєструє цей воркер і в зручний момент (наприклад, після першого дзвінка) просить дозвіл
   на сповіщення. Підписку надсилає нашому бекенду разом з токеном користувача.
3. Бекенд на вхідний дзвінок надсилає пуш. Сповіщення показує ім'я, дії «Відповісти» і «Відхилити».
4. «Відповісти» відкриває сторінку сайту з віджетом, і віджет одразу відкриває вхідний дзвінок.
   Сповіщення зникає, коли дзвінок прийнято на іншому пристрої, скасовано або минув таймаут.
5. Якщо сайт не розмістив `dialer-sw.js` або користувач не дав дозвіл, вхідні приходять лише у відкритий віджет.

### Контакти й історія

Список контактів та історію дзвінків віджет бере з нашого бекенду за токеном користувача.
Сайт-господар їх не передає. Оновлення (статус «у мережі», нові пропущені) приходять тим самим WebSocket, що й сигналізація.

### Хостинг

Поки що для тестування застосунок хоститься на **GitHub Pages** з гілки `dev`, бекенд на Fly.io:

| Шлях | Що там |
|---|---|
| `/dialer/` | застосунок `apps/web` (`entries/app.ts`): вхід за номером і кодом, контакти, дзвінки |

- Збирає й публікує GitHub Actions після пушу в `dev` (`.github/workflows/pages.yml`): `apps/web` з `base: './'` (відносні шляхи)
  і `VITE_SERVER_URL=https://dialer-chat-server.fly.dev`. Маршрути в hash (`#/login`), бо Pages не віддає `index.html` для довільних шляхів.
- `apps/web` збирає дві сторінки: `index.html` (застосунок) і `widget.html` (віджет для iframe з `embed.js`). На Pages лише застосунок;
  віджет, `embed.js` і сторінка демо працюють локально (див. [demo.md](demo.md)).
- `sw.js` з'явиться разом із пушами (беклог, «Пуш-сповіщення про вхідні»).
- Pages віддає сайт по HTTPS, тож камера й мікрофон працюють.
- Обмеження: не можна задати свої HTTP-заголовки (CSP, `Permissions-Policy`), а сторінка демо
  лежить на тому самому домені, що й віджет. Роботу з чужого домену треба окремо перевірити з іншого хостингу
  або з локального сервера.
- Продакшен-хостинг обиратимемо пізніше.

### Стан дзвінка

Стор `useCallStore` (Pinia) з машиною станів, як у демо:

``` text
idle ──call()──▶ ringing ──answered──▶ connected ──hangup──▶ idle
idle ◀─busy / timeout / cancel── ringing
idle ──incoming──▶ incoming ──accept──▶ connected
idle ◀─reject / timeout── incoming
```

Підстани розмови: утримання (своє й співрозмовника), відновлення з'єднання, співрозмовник зник,
якість сигналу, мікрофон і камера з обох боків. Результат завершеного дзвінка (`busy`, `timeout`,
`missed`) записується в історію.

Переходи робляться лише через дії стору. Компоненти читають стан і викликають дії, але не змінюють його напряму.

### Медіа

`shared/media` ізолює LiveKit від решти коду:

- підключення до кімнати за токеном від бекенду;
- публікація мікрофона й камери, увімкнення й вимкнення треків;
- події кімнати (`Reconnecting`, `ParticipantDisconnected`, `TrackMuted`, `ConnectionQualityChanged`)
  перетворюються на дії стору: відновлення з'єднання, співрозмовник зник, мікрофон вимкнено, слабкий сигнал;
- вибір пристроїв (мікрофон, камера, динамік).

### Сигналізація

Виклик, відповідь, «зайнято» й таймаути йдуть через WebSocket до бекенду, а не через LiveKit.
Таймери дзвінка (60 с на відповідь) рахує сервер, клієнт лише показує відлік.

### Звуки

Гудки, «зайнято», мелодії вхідного й утримання переносимо з демо (Web Audio).
Аудіоконтекст розблоковується першим жестом користувача, як у демо (потрібно для iOS Safari).

### Доступність

- Live-регіон з коротким описом стану дзвінка для скрінрідерів.
- Усі кнопки мають `aria-label`, перемикачі — `aria-pressed`.
- Верстка працює на ширині телефона.

### Відкриті питання

- Продакшен-хостинг віджета (відкладено, поки тестуємо на GitHub Pages).

### Рішення

- Вбудовування через iframe і завантажувач `embed.js`.
- На сайті віджет — плаваюча кнопка, що відкриває панель.
- Контакти й історія — з нашого бекенду.
- Вхідні, коли вкладку закрито, — через Web Push.
- Сайти-господарі розміщують у себе `dialer-sw.js` для пушів.
- На iPhone пуші лише для сайтів, доданих на головний екран; це прийнятно.
- Для тестування хостимо на GitHub Pages.
- Демо — окрема сторінка з вбудованим віджетом; вона ж тестовий сайт-господар.
- Вхід у демо за ім'ям і номером без підтвердження кодом, лише номери `+380`.
- У демо в контактах усі демо-користувачі.
