# Архітектура

Цільова архітектура дзвонілки. Демо в `index.html` лише імітує інтерфейс (див. [demo.md](demo.md)),
цей документ описує, як будувати справжній застосунок. Розділи додаються поступово.

## 1. Фронтенд: Vue SPA

### Стек
| Що | Вибір | Навіщо |
|---|---|---|
| Фреймворк | Vue 3, Composition API, `<script setup>` | реактивний стан замість ручного `render()` з демо |
| Мова | TypeScript | типізовані стани дзвінка й події сервера |
| Збірка | Vite | швидкий dev-сервер, HTTPS для доступу до камери |
| Маршрутизація | Vue Router | екрани списку, історії, налаштувань |
| Стан | Pinia | спільний стан дзвінка для всіх екранів |
| Медіа | `livekit-client` | аудіо й відео через LiveKit |
| Переклади | vue-i18n | українська за замовчуванням, рід у текстах («вимкнула»/«вимкнув») |
| Тести | Vitest, Vue Test Utils, Playwright | юніт-тести сторів і e2e-сценарії з демо |
| Якість коду | ESLint, Prettier | єдиний стиль |

### Структура папок
Код SPA лежить у `web/`:
```
web/
  src/
    app/          # main.ts, App.vue, router, i18n
    pages/        # екрани-маршрути: Contacts, Recents, Settings
    features/
      call/       # екрани дзвінка, стор, машина станів
      contacts/
      recents/
    shared/
      ui/         # кнопки, аватари, іконки
      media/      # обгортка над livekit-client, пристрої, камера
      sounds/     # гудки й мелодії через Web Audio
      api/        # HTTP-клієнт і WebSocket сигналізації
  tests/e2e/
```

### Маршрути
- `/` — контакти;
- `/recents` — історія дзвінків;
- `/settings` — пристрої, звук.

Екран дзвінка не є маршрутом: це шар поверх поточної сторінки, який керується стором дзвінка.
Так дзвінок не обривається під час навігації, а згорнутий дзвінок показується плашкою на будь-якому екрані.

### Стан дзвінка
Стор `useCallStore` (Pinia) з машиною станів, як у демо:

```
idle ──call()──▶ ringing ──answered──▶ connected ──hangup──▶ idle
idle ◀─busy / timeout / cancel── ringing
idle ──incoming──▶ incoming ──accept──▶ connected
idle ◀─reject / timeout── incoming
```

Підстани розмови: утримання (своє й співрозмовника), відновлення з'єднання, співрозмовник зник,
якість сигналу, мікрофон і камера з обох боків. Результат завершеного дзвінка (`busy`, `timeout`,
`missed`) записується в історію.

Переходи робляться лише через дії стору. Компоненти читають стан і викликають дії, але не змінюють його напряму.

### Медіа
`shared/media` ізолює LiveKit від решти коду:
- підключення до кімнати за токеном від бекенду;
- публікація мікрофона й камери, увімкнення й вимкнення треків;
- події кімнати (`Reconnecting`, `ParticipantDisconnected`, `TrackMuted`, `ConnectionQualityChanged`)
  перетворюються на дії стору: відновлення з'єднання, співрозмовник зник, мікрофон вимкнено, слабкий сигнал;
- вибір пристроїв (мікрофон, камера, динамік).

### Сигналізація
Виклик, відповідь, «зайнято» й таймаути йдуть через WebSocket до бекенду, а не через LiveKit.
Таймери дзвінка (60 с на відповідь) рахує сервер, клієнт лише показує відлік.

### Звуки
Гудки, «зайнято», мелодії вхідного й утримання переносимо з демо (Web Audio).
Аудіоконтекст розблоковується першим жестом користувача, як у демо (потрібно для iOS Safari).

### Доступність
- Live-регіон з коротким описом стану дзвінка для скрінрідерів.
- Усі кнопки мають `aria-label`, перемикачі — `aria-pressed`.
- Верстка працює на ширині телефона.

### Відкриті питання
- Чи потрібна PWA (встановлення, офлайн-оболонка, пуш-сповіщення про вхідні)?
- Авторизація: який провайдер і де зберігати токен?
- Де хостимо SPA: статичний хостинг чи разом з бекендом?
