# Як влаштоване демо

Інтерфейс дзвінків живе в `apps/web` (застосунок і віджет), про нього [components.md](components.md), стани й сценарії дзвінка в [signaling.md](signaling.md).
Клікабельного прототипу в одному файлі (`index.html`) більше немає: еталон вигляду це `design/dialer.pen`. Тут описано сторінку демо й демо-співрозмовників.

## Демо-співрозмовники (боти)

Їх створює сервер (`apps/server/src/bots/scenarios.ts`), у списку контактів вони завжди «в мережі»:

- Олена (`bot:olena`) приймає дзвінок через 3,5 с і працює як **ехо-тест**: заходить у кімнату LiveKit (`apps/server/src/bots/echo.ts`, `@livekit/rtc-node`) і повертає співрозмовнику його ж звук і відео. Видно й чути, що передає камера й мікрофон, і яка затримка туди й назад. Камеру вимкнули: відео Олени зникає. Із вимкненим LiveKit (без `LIVEKIT_*`) Олена відповідає лише в сигналізації, без медіа. Через динамік слухавки можливий зворотний зв'язок: для тесту користуйтесь навушниками.
- Андрій (`bot:andriy`) не відповідає: через 8 с екран «Без відповіді».
- Support (`bot:support`) одразу повертає «Зайнято».

Решта користувачів це справжні люди, які увійшли на сайті: їм можна дзвонити з другої вкладки. Сценарії обриву зв'язку, слабкого сигналу, утримання,
мікрофона й камери співрозмовника відтворюються справжніми діями в розмові (див. [signaling.md](signaling.md)).

## Сторінка демо (`demo/`)

Сторінка з [architecture.md](architecture.md#сторінка-демо): сайт-господар з входом і вбудованим віджетом.

- **Вхід.** Форма «ім'я + номер `+380`» без підтвердження. «Бекенд» імітується в `localStorage`:
  - `dialer.demo.users` — усі, хто входив (`{ phone, name }`), той самий номер перезаписує запис;
  - `dialer.demo.session` — токен, ім'я й номер поточної вкладки;
  - `dialer.demo.theme` — вибрана тема.
- **Токен** має вигляд `demo.<номер>.<час спливання>` і живе 30 хв. Справжній токен буде непрозорим.
- **`demo/embed.js`** імітує завантажувач: `Dialer.mount` малює плаваючу кнопку й панель з iframe, у якому Vue-віджет `apps/web`
  (типово `http://localhost:5173/widget.html`, тож спершу запустіть `corepack pnpm --filter @dialer/web dev`; інша адреса: атрибут `data-widget`
  чи параметр сторінки `?widget=…`). Повертає API `on`, `open`, `close`, `setTheme`, `setToken`, `call`, `unmount`.
- **Повідомлення** між віджетом і сторінкою (`postMessage`):
  - віджет → сторінка: `ready`, `state` (стан дзвінка), `close` (Esc), `token:expired`;
  - сторінка → віджет: `theme`, `token`, `call`.

## Режим зі справжнім сервером (`?server=`)

З параметром `?server=http://localhost:8787` сторінка демо працює на справжньому бекенді (див. [local-development.md](local-development.md)):

- вхід через `POST /demo/login`, сесія в `sessionStorage` (кожна вкладка окрема, тож у двох вкладках можна бути двома людьми);
- `Dialer.mount({ server })` передає адресу у віджет, віджет підключається до `/ws`, контакти й боти приходять від сервера, дзвінки йдуть через сигналізацію, аудіо й відео через LiveKit;
- без параметра сервер береться з `<meta name="dialer-server">`; у репозиторії він порожній, тож віджет без сервера нічого не покаже.
