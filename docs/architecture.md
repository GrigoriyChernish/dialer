# Архітектура

Цільова архітектура дзвонілки. Демо в `index.html` лише імітує інтерфейс (див. [demo.md](demo.md)),
цей документ описує, як будувати справжній застосунок. Розділи додаються поступово.

## 1. Фронтенд: Vue SPA

### Як поставляється
Продукт — **віджет**, який вбудовується в сторонні сайти й застосунки. Окремого сайту дзвонілки немає.

| Режим | Для кого | Вхід |
|---|---|---|
| **Віджет** (основний) | користувачі сайту-господаря | без логіна: сайт-господар передає токен |
| **Демо** | показ продукту, тестування | за номером телефону |

Обидва режими — один і той самий Vue-застосунок, різниця лише в точці входу й способі отримати токен.

### Стек
| Що | Вибір | Навіщо |
|---|---|---|
| Фреймворк | Vue 3, Composition API, `<script setup>` | реактивний стан замість ручного `render()` з демо |
| Мова | TypeScript | типізовані стани дзвінка й події сервера |
| Збірка | Vite | швидкий dev-сервер, HTTPS для доступу до камери |
| Стилі | Tailwind CSS 4 | утиліти в шаблонах, дизайн-токени в CSS через `@theme`, світла й темна теми |
| Маршрутизація | Vue Router, `createMemoryHistory` | екрани всередині віджета, не чіпаючи URL сайту-господаря |
| Стан | Pinia | спільний стан дзвінка для всіх екранів |
| Медіа | `livekit-client` | аудіо й відео через LiveKit |
| Переклади | vue-i18n | українська за замовчуванням, рід у текстах («вимкнула»/«вимкнув») |
| Тести | Vitest, Vue Test Utils, Playwright | юніт-тести сторів і e2e-сценарії з демо |
| Якість коду | ESLint, Prettier | єдиний стиль |

### Структура папок
Код SPA лежить у `web/`:
```
web/
  src/
    app/          # App.vue, router, i18n
    entries/
      widget.ts   # точка входу віджета: токен і налаштування від сайту-господаря
      demo.ts     # точка входу демо: вхід за номером телефону
    embed/        # embed.js: невеликий завантажувач, який сайт-господар підключає до себе
      styles/     # main.css: підключення Tailwind і дизайн-токени
    pages/        # екрани-маршрути: Contacts, Recents, Settings
    features/
      call/       # екрани дзвінка, стор, машина станів
      contacts/
      recents/
    shared/
      ui/         # кнопки, аватари, іконки
      media/      # обгортка над livekit-client, пристрої, камера
      sounds/     # гудки й мелодії через Web Audio
      api/        # HTTP-клієнт і WebSocket сигналізації
  tests/e2e/
```

### Стилі
Tailwind CSS 4 підключається через Vite-плагін `@tailwindcss/vite`. Окремого `tailwind.config.js` немає:
у v4 налаштування пишуться прямо в CSS.

```css
/* web/src/app/styles/main.css */
@import "tailwindcss";

/* варіант dark: спрацьовує за атрибутом, а не лише за системною темою */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

/* світла тема */
:root {
  --bg: #eef0f6; --card: #fff; --fg: #12151f; --mute: #5b6478; --line: rgba(20, 24, 38, .1);
}
/* темна тема */
[data-theme="dark"] {
  --bg: #0b0d12; --card: #161a24; --fg: #f3f5fa; --mute: #98a2b6; --line: rgba(255, 255, 255, .12);
}

/* inline: утиліти посилаються на змінні, тому самі перемикаються разом з темою */
@theme inline {
  --color-bg: var(--bg);
  --color-card: var(--card);
  --color-fg: var(--fg);
  --color-mute: var(--mute);
  --color-line: var(--line);
  --color-accent: #6366f1;
  --color-call-ok: #22c55e;   /* кнопка «Прийняти» */
  --color-call-bad: #ef4444;  /* кнопка «Завершити» */
  --color-warn: #fbbf24;      /* відновлення, слабкий сигнал */
}
```

- Кольори, відступи й радіуси беремо з демо й оголошуємо як токени в `@theme`. Tailwind сам створює з них утиліти,
  наприклад `bg-card`, `text-mute`, `bg-call-ok`.
- У компонентах пишемо утиліти прямо в шаблоні. Повторювані елементи (круглі кнопки дзвінка, аватари)
  виносимо в компоненти `shared/ui`, а не в класи з `@apply`.
- Анімації з демо (пульсація аватара, хвиля голосу, спінер відновлення) описуємо через `@keyframes` у `main.css`
  і токени `--animate-*` у `@theme`.
- Поважаємо `prefers-reduced-motion`: анімації вимикаються варіантом `motion-reduce:`.

Повний перелік токенів — у [design-system.md](design-system.md), каталог компонентів — у [components.md](components.md).

### Теми
Дві теми: **світла** й **темна**. Кольори обох узяті з демо.

- Режим теми: `auto` (за `prefers-color-scheme`, змінюється разом із системою), `light` або `dark`.
- **У віджеті** режим задає сайт-господар у налаштуваннях віджета, щоб віджет пасував до його дизайну.
  За замовчуванням `auto`. Сайт-господар може змінити тему на льоту (наприклад, коли в нього самого перемикається тема).
- **У демо** користувач обирає тему в налаштуваннях, вибір зберігається в `localStorage`.
- Композабл `useTheme` у `shared/ui` виставляє на `<html>` атрибут `data-theme="light"` або `"dark"`
  і для `auto` слухає зміни `matchMedia`.
- Щоб віджет не блимав не тією темою при завантаженні, тема передається вже в URL iframe
  і виставляється до запуску Vue.
- Компоненти використовують семантичні кольори (`bg-card`, `text-fg`, `text-mute`), тож працюють в обох темах
  без змін. Варіант `dark:` лише для рідкісних винятків, наприклад тіней чи зображень.
- Кожен екран перевіряємо в обох темах; контраст тексту не нижче WCAG AA.
- `color-scheme` на `<html>` відповідає темі, щоб системні елементи (скролбари, поля вводу) теж перемикались.

### Маршрути
Маршрути внутрішні: Vue Router працює з `createMemoryHistory`, тому навігація у віджеті не змінює URL і
історію браузера сайту-господаря.

- `/` — контакти;
- `/recents` — історія дзвінків;
- `/settings` — пристрої, звук (і тема — лише в демо).

Екран дзвінка не є маршрутом: це шар поверх поточної сторінки, який керується стором дзвінка.
Так дзвінок не обривається під час навігації, а згорнутий дзвінок показується плашкою на будь-якому екрані.

### Вбудовування
Пропозиція: віджет працює в **iframe**, який створює невеликий завантажувач `embed.js`.

```html
<script src="https://<наш-домен>/embed.js"></script>
<script>
  const dialer = Dialer.mount('#dialer', {
    token: '<токен від бекенду сайту-господаря>',
    theme: 'auto',
    locale: 'uk',
  });
  dialer.on('call:ended', (e) => { /* … */ });
  dialer.setTheme('dark');
</script>
```

- `embed.js` створює iframe з `allow="camera; microphone; autoplay; display-capture"`: без цього браузер
  не дасть доступу до камери й мікрофона всередині iframe.
- Сайт-господар і віджет спілкуються через `postMessage`. Обидва боки перевіряють `origin` повідомлень.
- API завантажувача: `mount`, `unmount`, `setTheme`, `call(contactId)`, події `ready`, `call:started`,
  `call:ended`, `incoming`, `error`.

Чому iframe, а не вбудовування прямо в сторінку (Web Component):
- стилі сайту-господаря не ламають віджет, а стилі віджета — сайт (Tailwind 4 у Shadow DOM працює не повністю);
- токен і медіапотоки ізольовані від скриптів сайту-господаря;
- віджет оновлюється на нашому боці без змін на сайті-господарі.

### Авторизація
- **Віджет.** Власного логіна немає. Бекенд сайту-господаря отримує в нашого бекенду короткоживучий токен
  користувача й передає його у `Dialer.mount`. Коли токен спливає, віджет надсилає подію `token:expired`,
  і сайт-господар передає новий через `dialer.setToken`.
- **Демо.** Вхід за номером телефону: номер → код з SMS → токен. Токен зберігається в `localStorage`.
  Екрани входу є лише в точці входу демо й не потрапляють у збірку віджета.

### Стан дзвінка
Стор `useCallStore` (Pinia) з машиною станів, як у демо:

```
idle ──call()──▶ ringing ──answered──▶ connected ──hangup──▶ idle
idle ◀─busy / timeout / cancel── ringing
idle ──incoming──▶ incoming ──accept──▶ connected
idle ◀─reject / timeout── incoming
```

Підстани розмови: утримання (своє й співрозмовника), відновлення з'єднання, співрозмовник зник,
якість сигналу, мікрофон і камера з обох боків. Результат завершеного дзвінка (`busy`, `timeout`,
`missed`) записується в історію.

Переходи робляться лише через дії стору. Компоненти читають стан і викликають дії, але не змінюють його напряму.

### Медіа
`shared/media` ізолює LiveKit від решти коду:
- підключення до кімнати за токеном від бекенду;
- публікація мікрофона й камери, увімкнення й вимкнення треків;
- події кімнати (`Reconnecting`, `ParticipantDisconnected`, `TrackMuted`, `ConnectionQualityChanged`)
  перетворюються на дії стору: відновлення з'єднання, співрозмовник зник, мікрофон вимкнено, слабкий сигнал;
- вибір пристроїв (мікрофон, камера, динамік).

### Сигналізація
Виклик, відповідь, «зайнято» й таймаути йдуть через WebSocket до бекенду, а не через LiveKit.
Таймери дзвінка (60 с на відповідь) рахує сервер, клієнт лише показує відлік.

### Звуки
Гудки, «зайнято», мелодії вхідного й утримання переносимо з демо (Web Audio).
Аудіоконтекст розблоковується першим жестом користувача, як у демо (потрібно для iOS Safari).

### Доступність
- Live-регіон з коротким описом стану дзвінка для скрінрідерів.
- Усі кнопки мають `aria-label`, перемикачі — `aria-pressed`.
- Верстка працює на ширині телефона.

### Відкриті питання
- Підтвердити вбудовування через iframe (альтернатива — Web Component).
- Як віджет показується на сайті: плаваюча кнопка в кутку, що відкриває панель, чи вбудований блок у сторінці?
- Список контактів: віджет бере його з нашого бекенду чи сайт-господар передає свій?
- Вхідні дзвінки, коли вкладку із сайтом закрито: потрібні пуш-сповіщення чи вхідні приходять лише у відкритий віджет?
- Де хостимо віджет і `embed.js`: статичний хостинг з CDN чи разом з бекендом?
