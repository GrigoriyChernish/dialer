# PWA та Web Push сповіщення

Специфікація PWA і Web Push для автономного застосунку `apps/web`. Роботу поділено на три етапи, кожен розгортається окремо:

| Етап | Зміст | Стан |
| :--- | :--- | :--- |
| **A** | Маніфест, іконки, `theme-color` | реалізовано |
| **B** | Підписка в Налаштуваннях, `push_subscriptions`, VAPID, `sw.js` | реалізовано |
| **C** | Дзвінок до адресата без мережі, дії «Відповісти» / «Відхилити» | заплановано |

**Межі.** Лише Android (Chrome та сумісні браузери). iOS відкладено: Web Push там потребує встановленого застосунку, не підтримує кнопки дій і вібрацію, тому окремих рішень для нього поки немає. Віджет (`widget.html`) поза межами: він живе в `iframe` на чужому сайті, і сервіс-воркер має бути на origin сайту-господаря (див. пункт 8 у [беклозі](../work/backlog/backlog.md)).

## Етап A. PWA і колір статус-бару

### Маніфест і іконки

Файли в `apps/web/public/` (Vite копіює їх у корінь збірки):

- `manifest.webmanifest`: `name` «Дзвонілка», `display: standalone`, `start_url: '.'`, `scope: '.'` (відносні шляхи, бо на GitHub Pages застосунок живе в `/dialer/`), `background_color` і `theme_color` темні.
- `icons/icon-192.png`, `icons/icon-512.png` і `icons/maskable-512.png` (значок слухавки на фоні `--bg` темної теми, для maskable контент у безпечній зоні 80 %). Генерує `scripts/make-icons.mjs` без залежностей.

Сервіс-воркера на етапі A немає: застосунок не працює офлайн, Chrome на Android пропонує встановлення і без нього.

### `theme-color`

Колір статус-бару й верхньої панелі браузера збігається з `--bg` поточної теми ([`tokens.css`](../apps/web/src/app/styles/tokens.css)).

- У `index.html` дві мета-теги з `media="(prefers-color-scheme: …)"`: світла `#eef0f6`, темна `#0a0c14`. Вони діють до запуску скриптів.
- `applyThemeColor(theme)` ([`shared/theme.ts`](../apps/web/src/shared/theme.ts)) викликається вотчером `prefs.theme` в `entries/app.ts`:
  - `light` / `dark`: пара з `media` прибирається, ставиться один тег без `media` з відповідним кольором (інакше системна тема перебила б вибір користувача);
  - `auto`: пара з `media` повертається.
- `theme_color` у маніфесті статичний (темний): вирішальне слово за мета-тегами.

## Етап B. Підписка і сервер

### Підписка в Налаштуваннях (`SettingsPage`)

Підписка не нав'язується, користувач вмикає її тумблером (рядок «Сповіщення про дзвінки», підказка «Коли вкладку закрито · лише цей пристрій», іконка `bell`). Дизайн: `Flow · Settings` (`Settings`, `Settings · notifications on`, `· notifications blocked`). Іконка `bell-ring`.

1. Дозвіл `default` → `Notification.requestPermission()`.
2. `granted` → `registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })`, ключ зі `hello.ok.vapidPublicKey`.
3. Клієнт надсилає `push.subscribe` з підпискою; вимкнення: `subscription.unsubscribe()` + `push.unsubscribe`.
4. Стан тумблера береться з `pushManager.getSubscription()`, а не з локальних налаштувань (інакше розійдуться).
5. `denied`: тумблер недоступний, підказка «Заблоковано в браузері» кольору `warn`.
6. Рядка немає, якщо браузер не вміє push (`serviceWorker`, `PushManager`, `Notification`) або сервер не віддав `vapidPublicKey`. Помилка підписки: підказка «Не вдалося увімкнути».

Логіка живе в `features/settings/push.ts` (`usePush`). Якщо сервер змінив ключ VAPID, стара підписка знімається й створюється нова.

При виході підписка знімається (`SettingsPage.logout`), щоб наступний користувач браузера не отримував чужі дзвінки. Після кожного завантаження сторінки і `hello.ok` застосунок повторно віддає серверу наявну підписку (`resyncPush`): сервер міг її втратити, а підписка з тим самим `endpoint` переходить до поточного користувача.

### Сервіс-воркер

`apps/web/public/sw.js` реєструється відносним шляхом `sw.js` (на Pages це `/dialer/sw.js`, область `/dialer/`) при вмиканні сповіщень. Без кешування й `fetch`. На етапі B він показує сповіщення «Вхідний дзвінок» (`tag: callId`, `requireInteraction`) на push `call.incoming`, закриває його на `call.ended`, а натискання фокусує вікно застосунку чи відкриває `registration.scope`. Кнопки дій додає етап C. Перевірка без сервера: DevTools → Application → Service Workers → Push з тілом `{"type":"call.incoming","callId":"c1","from":{"name":"Олена"}}`.

### Сервер

- Таблиця `push_subscriptions` (міграція `006_push_subscriptions.sql`): `endpoint` (ключ), `user_id`, `site_id`, `device_id`, `p256dh`, `auth`, `created_at`; зовнішній ключ на користувача з каскадним видаленням.
- Ключі VAPID лише зі змінних `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (секрети Fly; пару створює `web-push generate-vapid-keys`). Генерація на льоту заборонена: після перезапуску всі підписки стали б недійсними. Без ключів push вимкнено, частково задані ключі — помилка конфігурації.
- Відправка: бібліотека `web-push`, інтерфейс `PushSender` (у тестах підміняється). Відповідь `404` / `410` видаляє підписку.
- **Безпека.** Сервер сам робить HTTP-запит на endpoint із підписки, тож endpoint перевіряється: `https` і хости відомих push-сервісів (FCM, Mozilla, WNS); інакше це SSRF.

## Етап C. Дзвінок до адресата без мережі (заплановано)

Зараз, якщо в адресата немає жодного пристрою в мережі, дзвінок завершується з `offline`. З push:

- адресат має підписки → дзвінок лишається `ringing` без WebSocket адресата, `offline` лише без підписок;
- після `hello` адресата очікуваний дзвінок приходить у `hello.ok.calls`;
- push надсилається лише на пристрої **без активного WebSocket**: сервіс-воркер зобов'язаний показати сповіщення на кожен push, тому «вікно відкрите, ігноруємо» не підходить.

| Подія на сервері | Сповіщення |
| :--- | :--- |
| Вхідний дзвінок | «Вхідний дзвінок від {Ім'я}», кнопки **Відповісти** / **Відхилити**, `requireInteraction`, `tag: callId`, `TTL` = залишок таймауту, `urgency: high` |
| `cancelled` / `timeout` | сповіщення з тим самим `tag` замінюється на «Пропущений дзвінок від {Ім'я}» |
| `answered_elsewhere` | сповіщення закривається |

- **Відповісти:** фокус наявного вікна + `postMessage`, або `clients.openWindow(registration.scope)`. Застосунок показує екран вхідного дзвінка з кнопкою; автоприйняття за посиланням немає (інакше будь-яке посилання вмикало б камеру й мікрофон).
- **Відхилити:** фоновий `POST /push/reject` з одноразовим токеном із payload (SW не бачить `localStorage`), дзвінок завершується з `rejected`. Вікно не відкривається.
- Це сповіщення, а не гудки: закритий застосунок мелодію не відтворює.
