# Структура проєкту

Як організовано репозиторій: що вже є і куди додавати нові частини.

## Дерево
```
dialer/
  AGENTS.md          # інструкції для агентів
  CLAUDE.md          # підключає AGENTS.md для Claude Code
  README.md          # що це за проєкт і як запустити
  index.html         # клікабельне демо інтерфейсу (є)
  docs/              # документація (є)
    README.md        #   зміст
    architecture.md  #   цільова архітектура
    demo.md          #   як влаштоване демо
    project-structure.md
  work/              # робочі матеріали команди й агентів (є)
    backlog/         #   беклог задач
    changelog/       #   ченджлог, файл на день: YYYY-MM-DD.md
  web/               # фронтенд, Vue SPA (буде)
  server/            # бекенд (буде, стек ще не визначено)
  .github/workflows/ # CI: лінт, тести, збірка (буде)
```

## Правила
- **Корінь** містить лише службові файли й папки верхнього рівня. Код застосунку в корінь не кладемо.
- **`docs/`** — довготривала документація: як усе влаштовано й чому.
- **`work/`** — робочий процес: що зробити (беклог) і що зроблено (ченджлог).
- **`web/`** і **`server/`** — окремі застосунки, кожен зі своїм `package.json` (або аналогом) і `README.md`
  з командами запуску. Внутрішня структура `web/` описана в [architecture.md](architecture.md#структура-папок).
- **Демо** `index.html` лишається в корені, поки не з'явиться `web/`. Потім його можна перенести в `demo/`.

## Відкриті питання
- Монорепозиторій з одним менеджером пакетів (наприклад, pnpm workspaces) чи незалежні `web/` і `server/`?
- Чи потрібна спільна папка для типів подій сигналізації, які використовують і фронтенд, і бекенд?
